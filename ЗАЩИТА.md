# Памятка для защиты КР №4

1. Откройте главную: это продолжение GamingLARP из КР №3. Покажите статистику из массива.
2. Откройте `js/data.js`: 8 объектов с одинаковыми полями, числовыми ценами и уникальными id.
3. Покажите каталог: карточки создаёт JavaScript, а не готовая разметка HTML.
4. Введите ` RAZER ` — останется 2 мыши. Выберите «Клавиатуры» — появится пустое состояние. Сбросьте фильтры.
5. Выберите «Только в наличии» — останется 6 товаров. Проверьте обе сортировки цены и названия.
6. Нажмите заявку на доступном товаре: он выбран в форме. Для недоступного товара кнопка отключена.
7. Отправьте пустую форму: появятся 4 ошибки. Заполните имя, e-mail, номер `+7 (999) 123-45-67`, поставьте согласие и повторите. Форма сообщит об успешной учебной проверке, отправки на сервер нет.
8. Покажите единственную дополнительную функцию — смену темы. Перезагрузите страницу: выбор сохраняется.
9. Откройте код и объясните функции ниже. В инструментах браузера проверьте Console. Поставьте точку остановки в `render` или обработчике `submit`, измените фильтр или отправьте форму и посмотрите значения переменных.
10. Покажите README и `git log --oneline`. Для СДО потребуется ссылка на отдельный удалённый репозиторий КР №4.

## Как объяснить код простыми словами

- Массив — список товаров; объект — набор свойств одного товара.
- `map` превращает каждый элемент в новый результат; `filter` отбирает подходящие; `find` находит один; `reduce` накапливает сумму.
- `sort` меняет массив, поэтому перед сортировкой делается копия через `[...items]`.
- DOM — представление HTML в виде объектов, с которыми работает JavaScript.
- `querySelector` находит элемент, `createElement` создаёт его, `append` помещает внутрь другого элемента.
- `textContent` записывает обычный текст и не выполняет переданную HTML-разметку.
- `state` содержит выбранные пользователем условия. Обработчик меняет состояние, затем `render` заново выводит подходящие карточки.
- `dataset` читает атрибуты `data-*`. Здесь идентификатор кнопки нужен для выбора товара.
- Делегирование — один обработчик у родительского блока вместо обработчика у каждой новой кнопки.
- `preventDefault` отменяет обычную отправку формы, чтобы проверить её в JavaScript.
- Клиентская проверка помогает пользователю, но при настоящем сервере нужна повторная серверная проверка.
- `localStorage` хранит тему в браузере между перезагрузками. Данные формы туда не записываются.

Перед защитой самостоятельно повторите показ и разберитесь в этих объяснениях. Технически работающий проект не заменяет устного понимания.
